# 2026-08-31 README 문서 검진

레포 구조 정리와 함께 README를 재작성하고 `reviewer-grounding`·`reviewer-fit`·`reviewer-readability`

어떻게 띄우는지를 끝까지 읽고 판단할 수 있게 한다"로 주입했다.

## reviewer-grounding — 사실 근거 (지적 12건)

고친 것은 다음과 같다.

- `/reissue`를 동작하는 기능으로 적었다. 발급 쿠키 이름(`refreshToken`)과 재발급이 찾는 이름(`refresh`)이
  달라 항상 400을 돌려주므로 「한계」로 내렸다.
- "컨테이너 치수와 팔레트 최대 적재 중량"이라 적었으나 `ContainerType`에는 치수가 없고 `PalletType`의
  `weight`는 자체 중량이다. 필드 구성대로 다시 적었다.
- 팔레트 다섯 종을 "KS 표준"이라 적은 것은 코드에 근거가 없어 규격 이름만 남겼다.
- `bootRun`도 `processResources`를 거쳐 React를 빌드한다. `--dry-run`으로 태스크 그래프를 확인하고
  `-x buildReact`를 기본 명령으로 바꿨다.
- API 표에 `PATCH /pallets`와 `PATCH /pallets/{container-id}/shipping`이 빠져 있었고,
  `DELETE /pallets`는 실제로 `/pallets/{pallet-id}`, `DELETE /containers`는 `?id=` 쿼리 파라미터다.
- "적재 위치는 사람이 정한다"는 `PalletService.shipPallets`의 자동 배치와 어긋나 "Bin-Packing이 아니다"로 좁혔다.
- Access 토큰 유효기간 불일치(로그인 1시간·재발급 10분), `SchedulerService`의 반복 쓰기,
  배송완료 상태 미도달을 「한계」와 「도메인 모델」에 새로 적었다.

넘긴 것은 없다. 못 훑은 각도는 「팀」 절의 포스터 대조와 실제 빌드 실행 둘이다.

## reviewer-fit — 양식·계약 (지적 8건)

고친 것은 파일:줄 표기를 심볼 이름으로 교체, 「한계」 불릿 라벨의 명사구화, 「핵심 기능」의 중복 서술
제거, 「사용 순서」 절 신설, API 표 권한 열의 표기 체계 통일, 「더 읽기」 절 신설이다.

**넘긴 지적 하나** — "API 표와 디렉터리 트리를 `docs/API.md`·`docs/ARCHITECTURE.md`로 분리하라"(severity
high)를 받아들이지 않았다. 끝난 학부 프로젝트의 공개 레포에서 README는 사실상 유일한 접점이고, 독자는
설치하려는 사용자가 아니라 프로젝트를 훑어보고 판단하려는 사람이다. 문서를 셋으로 늘리는 것이 `SIMPLE`과
어긋나며, 이번 작업의 요청 자체가 파일 구조를 알아보게 하는 것이라 트리는 본문에 있어야 값을 한다.

**미결 하나** — 공개 레포(`Capstone-Cosmos/Container_Simulator_Web`)인데 라이선스가 없다. 저작권이 팀원
세 사람 공동이라 사용자와 팀원이 정할 일로 남긴다.

## reviewer-readability — 전달 방해 (지적 16건)

고친 것은 첫 문단의 팔레트 부연, 「디렉터리 구조」 마지막 문단의 무너진 주어, 「사전 준비」의 결론 선행
배치, 상태 표 한 셀의 개조식과 문장 혼용, 소제목 셋의 명사구화, 「배경」을 「핵심 기능」 위로 이동,
세 절의 첫 문장 신설, `CRA`와 `Create React App` 용어 통일, 넓은 말('경로'·'지점') 교체,
용어 부연(`ddl-auto`·glTF·PBR·목 API·JWT), 연결어미 뒤 쉼표 정리, `A가 아니라 B` 대구 감축이다.

**넘긴 지적 하나** — "동작 화면 캡처를 붙여라"(severity medium)는 반영하지 못했다. 레포에 실행 화면
스크린샷이 없고 지금 띄울 MySQL 환경도 없어 만들 수 없다. 사용자가 직접 띄워 한 장 찍어 「핵심 기능」
위에 붙이면 이 문서의 값이 가장 크게 오른다.
